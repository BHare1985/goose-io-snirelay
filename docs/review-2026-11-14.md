# External review of conn.goose and handler.goose (2026-11-14): what was checked, what was true

Two reviews (one per file) and a third pass with the Goose language specification arrived as pasted text. **Nothing in them was taken on trust**: each claim was read
against the code (and, where the kernel was involved, against an experiment) before anything was changed. This page keeps the verdicts so that the next reader
does not redo the work, and so that a claim that was rejected is not "fixed" later by someone who does not know why.

Rule applied to every item: a behaviour change gets a red test first (`design/05-requirements.md`, RT-18 to RT-20); a change that cannot be reached by a
test (an `epoll_ctl` that fails only when the kernel is out of memory) says so; speed-only suggestions are skipped unless they are free, because the project
rule is to optimise only when more than 25% slower than the C proxy (`docs/status.md`).

## Confirmed and fixed (v0.6.0)

| Claim | Verdict | Where / test |
|---|---|---|
| `_ready` and `_waiting_reads` grow without bound under sustained load | **True.** Both were emptied only when head met tail; a connection that hits the 64 KB budget re-queues itself before that, so the list grew one entry per pass for as long as the load lasted. They are now compacted. `Stats.ready_len` / `waiting_len` expose the lengths. | RT-18a, RT-18b `queues_test` |
| `_close_connection` returns `out_buffers` before the slot is marked dead | **True.** A closing connection that was itself waiting for a buffer was woken by its own freed buffer, so a later waiter stayed asleep while a buffer was free. The slot is now marked dead first. | RT-19a `handler_edges_test` |
| `send` with an empty queue and an empty pool never gets its `Writable` | **True**, and it broke the documented promise ("after a false you get exactly one Writable once there is room"). A refused sender now waits in the same list as readers and is woken when a buffer returns. A send that can never fit (more than 4 buffers) is refused without promising one. | RT-19b |
| `EPOLLERR` closes a forwarded connection before its pending bytes are read | **True for the server side**: Linux keeps data that arrived before an RST readable (checked), and a server that answers and then aborts (`close` with unread request bytes) is common, so the client lost the response. Fixed for the server socket. **Not changed for the client socket**: a client that reset is gone, and forwarding its last bytes to a backend only wastes the backend's work. | RT-20a, RT-20b `server_rst_test` |
| `_flush_output` does not count progress as activity | **True** (the forwarding path did). A slow reader of a full queue could be closed as idle while bytes were moving. | RT-19c |
| `forward` accepts a connection that was shut down or whose peer already ended | **True** for `shutdown_write` and for `PeerEof`. Both are refused now. | RT-19d |
| `_sweep_timeouts` lets the idle timeout end a dial that is still connecting | **True** when `connect_ms` is longer than `idle_timeout_ms`. The dial's own deadline (`_expire_dials`) decides now. | RT-19e |
| Unchecked `epoll_ctl` in `_connect_to` and `_register_client_edge` | **True**, only reachable when the kernel is out of memory, so there is no test. Both fail at once now. | by reading |
| `retries` is counted when the remaining addresses were cleared by `SetAddr` | **True**, cosmetic. | RT-19f |
| Stale comments, unused variable, the redundant `tag` parameter of `_start_handling`, `_WAKEUP_BUDGET` in the middle of the `_STATE_*` constants | **True.** Cleaned. | by reading |

## Rejected, with the reason

| Claim | Why not |
|---|---|
| Buffer starvation in `_pump_direction` (a connection retakes the buffer it just freed) | Bounded, not starvation. The woken reader is queued on `_ready` and runs on the next pass; the connection that retook the buffer must stop after `_WAKEUP_BUDGET` (64 KB) in any case. Yielding on every free buffer would cost throughput under pressure for no change in who is served. |
| `_batch_window` can sleep while `_ready` has work | The loop only enters the window when `wait_ms > 0`, and `wait_ms` is 0 whenever `_ready` (or a policy request) is not empty (`engine.goose`, `_serve_loop`). |
| `dial` leaves `_dial_due` at the failed dial's deadline | Self-correcting: the loop wakes at that time, `_expire_dials` recomputes `_dial_due` from the live dials. At worst one early wake-up. |
| Client `EPOLLERR` during `_STATE_CONNECTING` should close at once | A recorded decision (the comment in `_dispatch_event`): the client's flags are kept, the connect finishes or fails first, and the first read or write finds the error. At most one wasted backend connect. |
| `_pause_milliseconds` is unused | It is used by the serve loop (`engine.goose`) when `epoll_wait` fails. |
| `(first_target + attempts) % count` can overflow `u8` | A target holds at most 8 addresses (`Target.addrs: Addr[..8]`), so the sum is at most 14. |
| Clearing `_override_targets[..].addrs` on close can change the caller's `Target` | Goose copies by value (no heap, no sharing): `push(to)` stores a copy. |
| The "clock is read here" comment in `send` is wrong | It is right: `_tag_allows` calls `c_boottime_ms()`; `_now_ms` is used only for `last_active_ms`. |
| `forward()` should adopt `to.tag` / `to.gen` for fencing | **A question, not a bug**: a forwarded connection keeps the tag of the route it arrived on. Whether the new target's tag should fence it too is an API decision for Charlie (open, see TODO). |
| `reset()` on a dial that has not opened should cancel it like `close()` | A small API inconsistency, not a defect; left for Charlie's decision. |

## Skipped on purpose (speed or taste, under the 25% rule)

Field order of `_ConnectionSlot` for alignment (Goose structs are packed, x86 does not care), `_target_of` returning a reference, hoisting `_buffer_slice`
out of the `_write_buffer` loop, assigning `dir.buf` only after a successful read, shifting only non-empty output slots, and `.resize` in `_take_buffer`
(once per buffer, at growth). Revisit only if a profile points there (`bench/RESULTS.md`).
